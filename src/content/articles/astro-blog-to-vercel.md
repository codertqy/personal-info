这个个人博客最开始只是保存在电脑里的一个项目。页面已经能运行，但我对它的技术栈、部署方式以及域名和服务器之间的关系并不清楚。于是这次我从“它到底是怎么工作的”开始，一步一步把网站发布到了互联网上。

## 先弄清楚技术栈

这个网站使用的是 **Astro + TypeScript + MDX**。

- Astro 负责把页面和文章构建成浏览器可以直接访问的静态 HTML；
- TypeScript 用来约束配置和页面数据；
- Markdown/MDX 用来保存文章正文；
- CSS 负责整套页面的视觉和响应式布局。

它没有传统网站常见的 Java 后端和数据库。构建完成后，产物主要是 HTML、CSS、JavaScript 和图片，因此非常适合放在 Vercel 这样的静态托管平台上。

## GitHub 和 Vercel 分别做什么

我把代码推送到了独立仓库 `codertqy/personal-info`。GitHub 在这里保存项目文件和每次修改记录，但它并不负责我当前网站的实际运行。

Vercel 与这个仓库连接后，会在代码发生变化时自动执行构建：

```text
本地修改 → 推送到 GitHub → Vercel 自动构建 → 网站更新
```

第一次发布完成后，我获得了一个 `vercel.app` 地址。即使暂时没有正式域名，其他人也可以通过这个地址访问网站。

## 没有云服务器也能绑定域名吗

可以。域名只是网站更容易记住的地址，Vercel 已经承担了托管和分发工作。以后购买域名后，只需要在 Vercel 项目里添加域名，再按照提示配置 DNS，不需要为了这个静态博客额外购买云服务器。

## 这次留下的结论

以前我会把“代码仓库”“服务器”“域名”和“部署平台”混在一起理解。实际走完一次流程后，它们的边界清楚了很多：GitHub 保存源代码，Astro 生成网站，Vercel 托管构建结果，域名则负责把访客带到这里。

这篇记录不是一份适用于所有项目的部署教程，而是我当前博客真实使用的方案。等以后加入更复杂的登录、数据库或后端功能时，我还会再重新评估架构。
